# 分析の視点

X とニュースで拾った論点を、公開データで検証して掲載するタブ。

## 更新手順

```bash
python insights/src/compute_signals.py   # data/signals.json を更新
# data/editions/YYYY-MM-DD.json を追加（signals.json の数値のみ引用する）
python insights/src/build_page.py        # output/ を生成
```

自動更新は次の2段階で動く。PCは使わない。

1. GitHub Actions の `insights-data.yml` が株価(Yahoo Finance)・経済指標(FRED)・JPXの信用取引データを取得し、`market-data` ブランチへ上書きする。NY引け後(21:15 / 21:40 UTC)とアジア引け後(16:30 / 17:00 SGT)に動く。
2. クラウド定期実行が、そのデータで分析して号を作り、main へ push する。
   - **分析の視点**(このページ): 月〜土の 06:00 SGT に開始し、06:20 頃に公開。前日の米国市場までを扱う。
   - **日本・アジア**(`data/asia/`、タブ「Japan & Asia」): 平日 18:00 SGT。その日の日本株とアジア市場を扱う(下の「日本・アジア版」)。

### 月曜(SGT)の号

土曜の号が金曜の米国市場を扱うので、月曜朝は新しい米国の取引日がない。この日は「週末版」として、週末のニュース、Xの話題、週明けの東京・アジアで注目される点を中心に、3〜5枚のカードで号を作る。数値は金曜までのデータを使い、その旨を `as_of` と `method` に書く。`big_moves` は金曜の動きで新しいものがなければ省いてよい。

### データが古いとき

`manifest.json` の `last_date` が期待する取引日より古ければ、5分ごとに `market-data` を取り直して最大30分待つ(`git fetch origin market-data` → 展開し直す)。それでも古ければ公開せず、報告して終了する(Yahoo側の未更新や Actions の遅延のため)。

### マーケットチャートの「日々の材料」

号を作ったら、対象の取引日の材料を `charts/data/news/YYYY-MM.json` に足す(分析の視点は `us`、日本・アジア版は `jp`)。形式は `{"YYYY-MM-DD": {"us": {"items": [{"title", "detail", "direction": "up|down|flat", "source": {"label", "url"}}]}, "jp": {...}}}`。その日の値動きに効いた材料を3点程度、報道で確認できたものだけ書く。騰落率は `charts/data/*_ohlc.json` と矛盾させない。既存の日付は上書きせず、足りない市場だけ足す。`charts/data/news` もコミットに含める。`charts/output` は作り直さない(ページは材料をクリック時に読み込むので、すぐ表示される。収録日の目盛は平日の Actions がページを作り直すときに更新される)。push 前の `git pull --rebase` が競合したら、`git rebase --abort` で戻し、自分の追加内容を控えて `git reset --hard origin/main` で最新に合わせ、追加をやり直してコミットし直す。過去分は別の定期実行がさかのぼって集める(`charts/README.md`)。

クラウド環境から Yahoo Finance には接続できないので、`compute_signals.py` と `fetch_market_data.py` は Actions でだけ動かす。
取得する銘柄は `data/universe.json` で管理する。S&P500 と日経225の採用銘柄は `daily-review/data` にある。

## 号に載せるセクション

カード(分析の視点)に加えて、各号に次の2つを載せる。どちらも editions の JSON に入れ、`build_page.py` が描画する(キーがなければ表示しない)。

### 大きく動いたもの(`big_moves`)

チャートを見て「お!」と思う動きを、株価に限らず、為替、商品、金利、センチメント指数、経済指標から選ぶ。誰もが知っている動き(S&P500、ドル円、金の大きな流れなど)より、知られていない動きを優先する。優先順位は次のとおり。

1. **前日の急変(最優先)**: 前日に「ピン」と動いて目を見張るもの。普段の値動き(直近250日の日次標準偏差)の何倍か(σ)と、同じ大きさの動きが過去に何回あったかで書く(例「1日 +5.75%(4.6σ)、過去3年で同じ大きさ以上は2回だけ」)。普段動かない国債、為替、ボラ指数の急変も対象。
2. **誰も見ていなそうな動き**: 国別株(インド、UAE、サウジ、カタール、ベトナム、トルコ、ブラジル、メキシコなど)が全世界株(ACWI)に対して1か月・3か月で大きく勝って(負けて)いるもの、マイナーな商品(ココア、豚肉、ウランなど)や通貨の大きな動き。
3. **センチメント**: VIX、VVIX、MOVE(米債ボラ)、OVX、GVZ、SKEW、VIXの期間構造、シカゴ連銀金融環境指数、政策不確実性指数、ハイイールド・CCCスプレッド、ミシガン大の信頼感・インフレ期待など。極端な水準や急変があれば載せる。AAII個人投資家調査、CNNのFear & Greed、BofAのファンドマネージャー調査など、データにない指標は WebSearch で確認し、報道値として載せてよい。
4. **長めの動き・経済指標**: 1か月の変化が分布の端にあるもの、何年ぶりかの高値・安値、経済指標の何年ぶりかの水準。

手順:

1. `python insights/src/scan_big_moves.py insights/data/analysis/YYYY-MM-DD_big_moves_candidates.json --asof <号の基準日(米国の最終取引日)>` で候補を出す。出力は優先順に `spikes_market`, `spikes_stocks`, `relative`, `sentiment`, `market`, `sp500`, `nikkei225`, `econ`。
   `--asof` を付けないと、取引途中の東京の値などが混ざる。
2. 急変には必ず理由を WebSearch で確かめ、確認できなければ「理由は確認できていない」と書く。`data_check` に「要確認」と出たもの(直前に逆方向の同規模の動き)はデータ誤りの可能性が高いので、報道で裏付けがない限り載せず、`big_moves_note` で触れる。
3. 8〜13個を選ぶ。同じ話は1〜2枚にまとめ、日本株、海外株、新興国、商品、センチメント、経済指標がばらけるようにする。前日の急変が少ない日は、そう書いたうえで「誰も見ていなそうな動き」を厚くする。
4. 各要素: `label`, `group`(「前日の急変・日本株」「隠れた動き・中東」「センチメント」など、種類が分かるように), `metric`, `since`(何年ぶり、分布のどこか), `comment`, `direction`(`up`/`down`), `series`(候補JSONの `series` をそのまま使う。相対の動きは `relative` の `series` がACWI比の推移), 任意で `source`({label, url})。
5. 号の `big_moves_note` に、前日の急変の有無、目立つ隠れた動き、センチメントの状態を2〜4文でまとめる。
6. 採用銘柄(S&P500、日経225)の履歴は約3年しかないので「過去3年で」と書く。月次の経済指標は最新月を書く。現地通貨建ての指数は為替の影響を含むので、全世界株との比較はドル建てETF(INDA、UAE、EWZなど)を優先する。

取得する銘柄は `data/universe.json` の `daily`、経済指標・センチメント指数(FRED)は `fred` で管理する。気になる市場がなければ追加する(次回から取得される)。

### 大物投資家の相場観(`investors`)

著名投資家(ヘッジファンド、資産運用会社、著名アナリストなど)の直近の相場観を一覧にし、傾向をまとめる。

1. WebSearch で、直近1〜2週間の発言・インタビュー・持ち高(13Fなど)を広く探す(人物は固定しない。例: ダリオ、ドラッケンミラー、チューダー・ジョーンズ、アックマン、バーリ、グリフィン、マークス、ガンドラック、ダイモン、フィンク、バークシャー、日本の著名投資家)。新しい発言がない人物は、前号の内容を日付付きで残してよいが、古いものは外していく。
2. `items`: `name`, `role`, `date`(発言の時期。不明なら「時期不明」), `topic`, `stance`(強気/弱気/中立/慎重/混在), `view`(要旨。長く引用しない), `source`({label, url}), `status`(報道/投稿の要約、未検証/二次情報 など)。新しい順に並べる。
3. `trend`: テーマ別に `theme`, `bull`, `bear`, `neutral` を書き、誰がどちら側かを並べる。
4. `summary`: 多数派はどちらか、論点の共通項、その日のカードや相場との関係、見方が割れている点を書く。日本の投資家の発言が見つからなければ、その旨を書く。
5. 13Fは四半期末時点の持ち高なので、その旨を書く。確認できない発言は載せない。

## 日本・アジア版(`data/asia/YYYY-MM-DD.json`)

その日の日本株とアジア市場で起きたことを整理し、翌朝に話題にできる形にする。スキーマは分析の視点と同じ(`cards`, `big_moves`, `x_topics`, `snapshot` など。`investors` は不要)で、`margin` を加える。ファイル名の日付はアジアの取引日。

カードの切り口(毎回すべてではなく、その日に当てはまるものを選ぶ):

- **普段と違う動き・前日と同じ動き・過去の似た局面**: 日経平均、TOPIX、グロース、韓国、台湾、香港、中国本土、インド、ASEAN の騰落と、普段の値動き(σ)、前日との相関、過去の似た日(同じ組み合わせの動き)とその後。
- **個別銘柄主導か、先物・指数主導か**: 日経平均とTOPIXの差(NT倍率)、日経225採用銘柄の値上がり比率と等加重平均、寄与度上位銘柄(日経平均は株価平均型なので、値幅の大きい値がさ株の影響が大きい)、1306/1321 の60分足で動きが特定の時間帯(寄り付き、SQ、昼休み明け、先物主導の急変)に集中したか、CME日経先物(NKD=F)との乖離。
- **決算**: その日に発表・反応した主要企業の決算の中身(売上・利益・見通し・受注・会社計画との差)と、同業種・取引先・他セクターへの波及(同業の騰落で確かめる)。
- **リスクを取りに行ったか避けたか、なぜか**: 業種別(ディフェンシブ対景気敏感、グロース対バリュー、半導体、銀行)、円・日本国債金利、アジア通貨、海外投資家の動き、ニュースの材料。
- アジア全域: 韓国・台湾の半導体、香港・中国の政策、インドの資金流入など、日本株に関係するものを優先する。

### 信用取引の需給(`margin`)

`market-data` の `margin_report.json`(`insights/src/margin_report.py` が作る)をそのまま `margin` にコピーし、次を加える。

- `comment`: 買い残の水準と増減、上位銘柄への集中、評価損益と上位100銘柄の合計(含み損の大きい銘柄は戻り売り、含み益は利益確定の圧力)、個人の信用売買の比率と差引、海外投資家との向きの違い。数値はレポートの値だけを使う。
- `reported`: 報道や証券会社が公表している全体の評価損益率など、データにない指標(例: 松井証券の信用評価損益率)を WebSearch で確認できた場合だけ `[{"label", "value"(日付も), "source": {label, url}}]` で載せる。

上位銘柄の平均取得単価は、JPXが公表する銘柄別の買残金額(約定価額ベース)÷買残株数で、制度信用・一般信用を合わせた買い建玉全体の平均。評価損益は最新の終値との比較で、手数料・金利は含まない。`top_agg` は買い残上位100銘柄の合計。銘柄別の信用残は申込日ベースで、公表は翌営業日。週次の全体残高は毎週火曜に前週末分が公表される。

## 取得データの注意

先物と為替の「前日終値」は、取得した時点では確定前の値のことがあり、後で更新される(11/12の金先物は3,882.3→3,918.9)。号の数値は取得時点のものと明記し、後で大きく違うと分かったら、その号の `method` に訂正を書く。

各号は固定スナップショットで、過去号はページ右上から参照できる。
X はタイムラインを直接取得せず、検索経由の投稿のみ扱う。投稿は要約し、未検証である旨を明記する。
